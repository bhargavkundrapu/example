# Explain Project Modules Clearly

> > ✅ **Quick Win:** Teach the system like subway map stations—inputs→stops→outputs.

---

## SEC-00_LESSON_ID

- **Lesson ID:** `M4-L3`
- **Lesson Title:** Explain Project Modules Clearly
- **Difficulty:** Intermediate
- **Time:** 16–24 minutes

---

## SEC-01_SKILL_OUTCOME

Explain 3–6 modules crisply without drowning in internals too early.

---

## SEC-02_WHY_THIS_MATTERS

Panels often stop you mid-way if you bury them. Modular explanation gives natural pause points.

---

## SEC-03_REAL_INTERVIEW_SCENARIO

**“Explain backend modules.”**

---

## SEC-04_FRAMEWORK_YOU_WILL_USE

**Name:** Module Subway Map (IN → STEP → OUT × N)

**Definition:** Each module answers: inputs, processing steps you can defend, outputs + failure mode.

---

## SEC-05_BAD_ANSWER_TRANSCRIPT

> “Everything connects… many files…”

---

## SEC-06_WHAT_WENT_WRONG

- No interface thinking.
- No boundaries.

---

## SEC-07_GOOD_ANSWER_TRANSCRIPT

> “Backend has three stations: Auth issues tokens after credential checks; Inventory stores items + states; Notifications schedules reminders—these integrate through one service boundary I documented.
If you want internals, I'll zoom into Inventory validation rules I wrote.”

---

## SEC-08_BREAKDOWN_LINE_BY_LINE

- Clear stations.
- Mentions handshake boundary.
- Offers drill-down permission.

---

## SEC-09_SHORT_VERSION

**3-module map**: name + responsibility + handshake line.

---

## SEC-10_LONG_VERSION

Add sequence diagram narration if interviewer engages.

## SEC-11_FOLLOW_UP_QUESTIONS


1. **Q:** "Failure mode per module?"
   **A:** Per module quickly—truthful troubleshooting.


1. **Q:** "Coupling regrets?"
   **A:** Honest redesign ideas.


1. **Q:** "Who owned what?"
   **A:** Fair credit map.


---

## SEC-12_CONFIDENCE_DELIVERY_TIPS

- **Voice:** speak clearly; emphasize names and truthful numbers slowly.
- **Pace:** slow down on technical words you can explain.
- **Pauses:** short silence beats extra “umm/like”.
- **Body / camera:** relaxed shoulders; stable camera; hands visible briefly.
- Use palm-height air map gestures lightly—stations left-to-right.

---

## SEC-13_PRACTICE_DRILL

Explain your project aloud **with only nouns forbidden** experiment: replace vague nouns (“stuff”) banned—forces precision.

---

## SEC-14_AI_MOCK_PRACTICE

### Prompt A (simulate interviewer ethically)

Module drill interruptions: “stop—define inputs.” Rules: communication practice ONLY. Forbidden: cheating on tests/assignments, feeding hidden answers during live assessments. Do not invent my achievements—ask factual follow-ups.

### Prompt B (structure + feedback)

Check module granularity (too fuzzy vs too deep). Rules: critique clarity, structure, honesty, pacing, confidence. Forbidden: rewriting my story with fabricated facts. Label anything unverifiable as VERIFY.

## SEC-16_COMMON_MISTAKES

- Explaining every file path.
- Skipping error handling honesty.
- Fake microservices seams.
- No clear API contract language.
- Confusing teammate modules as yours silently.
